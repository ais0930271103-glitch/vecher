# Публикации и база подключения — кандидат 0.6.0 (11)

Утверждённый план: [CONTENT_AND_CONNECTIVITY_PLAN.md](CONTENT_AND_CONNECTIVITY_PLAN.md).
Дата подготовки: 23 октября 2026 года, Europe/Moscow.

Это первый проверяемый этап плана. Последний подтверждённый владельцем
установленный APK — 0.5.0 (10). Исходники кандидата, результат CI, обновление
API, подписанный APK и проверка на телефонах — отдельные состояния выпуска.

## Что изменено

Существуют пять прежних разделов. В «Сегодня» и «Вместе» появился вход
в публикации; в «Я» доступны личные материалы и сохранения. Предыдущая
видеолента и старые отправленные ролики доступны по прежним маршрутам.

- Читаемые экраны поста и инструкции: заголовки, абзацы, списки, автор,
  источники и продолжение серии. Текст не зависит от запуска плеера.
- Режимы «Для меня», «Подписки», «Для нас», «Сохранённое»; поиск внутри
  выбранного набора. Пустой выбор тем требует явного выбора, а не подмешивания
  произвольного материала.
- Личные подписки, «Полезно», сохранение, скрытие публикации и автора.
  Скрытие автора можно отменить. Личные отметки партнёру не передаются.
- Отдельные общие темы и язык. Личные интересы не объединяются автоматически.
  Курсор привязан к текущим настройкам и снимку каталога; устаревший набор
  обновляется с начала вместо склейки разных версий.
- «Обсудить» открывает редактируемый обычный текст в чате: заголовок
  и аннотация. Отправка происходит только по кнопке пользователя. Это
  совместимый текст, а не обещание открываемой карточки у старого APK.
- PIN и уход в фон приостанавливают запросы нового раздела. Смена аккаунта
  или подтверждённая смена пары очищает прежний личный контекст. Чтение
  не записывает время, паузы или свайпы.
- Обычное переподключение сохраняет черновик чата. Перед отправкой после
  восстановления связи приложение подтверждает текущую пару; сервер
  дополнительно проверяет переданный `expected_pair_id`. Старые APK могут
  продолжать отправлять прежние запросы без этого поля. Сообщение для
  прежней пары отклоняется до записи текста, файлов и уведомлений.

Контракт сервера и публикации: [backend/CONTENT.md](backend/CONTENT.md).
Миграция `0005_content` добавляет три таблицы; личные и общие настройки
используют прежнее шифрование проекта. Существующие таблицы не переписываются.
Gate запуска требует новую ревизию и наличие новых таблиц. Возврат старого
API после миграции требует специально проверенной совместимой сборки.

## Публикация без APK

Staging монтирует отдельный каталог публичного содержания только для чтения.
`prepare-content.py` один раз помещает туда стартовый выпуск и сохраняет уже
существующую публикацию. Каталог доступен API даже при deploy с `umask 077`.
Приватные вложения, ключи и БД в этот каталог не помещаются.

`python -m app.publish_content` проверяет весь кандидат, ссылки, уникальные
ID, согласованность серий и размер. Последующая публикация требует ожидаемую
ревизию, использует блокировку и атомарную замену. Следующий запрос читателя
увидит новую версию без пересборки APK и перезапуска API. Снимаемый материал
получает `active:false`, его стабильный ID не переиспользуется.

Настроенная редакторская панель Directus и её автоматический экспорт
ещё не входят в этот кандидат. Подготовка проверенного JSON и CLI дают
работающий путь публикации до подключения панели.

## Подключение приложения

Общий Dio-клиент используется для входа, данных, чата, сигналинга звонков,
публикаций и проверки/загрузки APK. Основной адрес задаёт `API_URL`.
`API_URLS` — JSON-массив дополнительно проверенных HTTPS origins; максимум
три разных адреса вместе с основным. Default — пустой массив. Новый адрес
не появляется автоматически и не принимается из содержимого ленты.

Безопасные GET/HEAD без тела могут попробовать доступные адреса по одному
в пределах общего ожидания. После успеха выбранный адрес сохраняется в памяти.
POST/PATCH/PUT/DELETE не повторяются автоматически. Если настроено несколько
входов и рабочий путь ещё не найден, перед записью выполняется безопасная
анонимная проверка доступности. Ошибка записи с неясным результатом по-прежнему
требует правил конкретной функции, а не общего повтора.

Токен передаётся только точным доверенным API origins. Перенаправления
запрещены, системная проверка TLS не отключена. HTTP допускается только
для отладочных loopback/emulator адресов. Системная маршрутизация, включая VPN,
сохраняется. Никакого принудительного обхода VPN нет.

WSS на основном API-host следует за успешно выбранным доверенным входом.
Отдельный настроенный realtime-host сохраняет собственный адрес. Уже
существующее восстановление и foreground polling остаются. Самостоятельный
сбой WSS не является переключателем всей API-маршрутизации.

При потере связи отдельная строка с повтором безопасной проверки находится
над экраном, не закрывая текст чата и не сбрасывая открытый черновик.
Она сообщает о связи с API, а не о доставке сообщения или фонового push.

Выход из аккаунта использует ограниченный запрос отвязки push с прежним
токеном, после чего забывает локальную сессию. Этот запрос не повторяется
автоматически и не даёт разрешения остальным запросам закрываемой сессии.
Если сеть недоступна, удаление регистрации push на сервере подтвердить нельзя.

Manrope и Comfortaa включены в APK. Файлы проверены по SHA-256 из закреплённой
версии google_fonts 6.3.3, содержат кириллицу; лицензии SIL OFL 1.1 приложены
и зарегистрированы. Отрисовка темы использует локальные Flutter fonts.

## Проверка обновления

`/app/version` сохраняет прежний `url` и добавляет реальные `sha256`, `bytes`
и относительный `download_path`. Новый клиент строит адрес только из
доверенного API origin. APK проверяется по полному размеру и SHA-256 до
передачи установщику. При отмене, ошибке или несовпадении частичный файл
удаляется. Проверка подписи остаётся у штатного Android-установщика;
Windows-сборщик дополнительно проверяет прежний сертификат, пакет и ABI.

Публикуемый `version.json` связывается с APK полями `sha256` и `bytes`.
Два файла не заменяются одной операцией: API обнаруживает несогласованную
пару и предлагает повторить позже. Проверка на клиенте также обнаруживает
замену файла во время загрузки. Старый APK продолжает читать прежние поля.

## Что ещё остаётся по утверждённому плану

1. Реально подготовленный независимый вход, ведущий к тому же API и БД,
   и проверка его маршрутов. Пока существует только основной адрес.
2. Постоянное пополнение, приглашённые авторы, изображения и полезные видео
   с собственной подготовленной медиадоставкой; редакционная панель Directus.
3. Защищённые кэш и устойчивая очередь сообщений; идемпотентные повторные
   загрузки файлов. Текущий API-клиент сам по себе их не заменяет.
4. Независимый TURN, отдельный TCP/TLS маршрут и проверки реального медиапотока.
   Сигналинг через API не превращает видео/звук в HTTP.
5. Проверка фонового push на конкретных устройствах и выбор дополнительного
   провайдера при необходимости. Резервный API не исправляет путь FCM→телефон.
6. Матрица Wi-Fi/мобильная сеть × VPN включён/выключен, смена сети в процессе,
   разные режимы у партнёров и обратная связь о содержании.

Автотесты проверяют код и контролируемые сбои. Они не доказывают доступность
на любом VPN, качество звонка у конкретного оператора или интерес к приложению.
Публикация следующего APK в прежний тестовый канал — после проверенной сборки;
разработка платного раздела остаётся отложенной.
