# Короткие видео: контракт первой бесплатной версии

Решение владельца: 22 октября 2026, «да делаем». Версия 0.5.0 (10).
Пять основных разделов сохраняются. Первая подборка — проверенные короткие
ролики со свободной лицензией и прямым HTTPS-воспроизведением; персональные
ленты сторонних соцсетей не импортируются. Каталог небольшой и конечный.

## API

Префикс `/videos`, обычное согласие `consented_user`. Совместные действия
дополнительно требуют действующую пару. Ответы не содержат чужих личных
предпочтений, отметок или истории. Видеокаталог не читает желания/чат для
персонализации. Заголовок чата для `ref_kind=video` выбирает сервер.

* `GET /videos/settings` → `topics: [{id,title}], personal_topics: [id],
  personal_revision: int, shared_topics: [id], shared_revision: int,
  has_pair: bool`. Общие темы явно общие; личные темы не копируются в них.
* `PUT /videos/settings/personal` и `PUT /videos/settings/shared`, тело
  `{topics: [id], revision: int}` → обновлённый ответ settings. Устаревшая
  revision → 409; клиент перечитывает данные и сообщает о конфликте.
* `GET /videos/feed?mode=personal|shared|saved&limit=48` →
  `{items: [Video], mode, catalogue_revision: str, total: int}`. Для shared
  используются только явно общие темы. Собственные скрытые ролики исключены;
  никакие личные отметки партнёра на выдачу не влияют. Saved — только личное.
  Уточнение после проверки APK 10: непустой выбор тем ограничивает состав
  personal/shared роликами хотя бы одной выбранной темы. Сортировка, лайки и
  день просмотра меняют порядок только внутри этого множества. Если подходящих
  роликов больше нет, выдача пустая; посторонние темы не подмешиваются. Пустой
  выбор означает стартовую подборку разных тем. Сохранённые, явно отправленные
  ролики и открытие по ID доступны независимо от текущего выбора интересов.
  Ограниченный каталог возвращается целиком в пределах лимита, без обещания
  бесконечной ленты. При обновлении учитываются свои просмотренные ролики.
* `GET /videos/shared` → такая же коллекция, `mode=shared_collection`:
  доступные ролики, явно отправленные друг другу в текущем чате. Удалённые
  сообщения не входят. Это не автоматическое раскрытие личных сохранений.
* `GET /videos/{id}` → Video; 404 для отсутствующего/отключённого ролика.
* `PATCH /videos/{id}/state`, тело с одним или несколькими полями
  `{liked?: bool, saved?: bool, hidden?: bool}` → Video. Идемпотентное задание
  значений, а не переключение. При скрытии личное сохранение не теряется.
* `POST /videos/{id}/viewed` → `{ok:true}`. Не чаще одного раза в день на
  ролик; только локальный день просмотра, без длительности и поведенческого
  профиля. Отправляется после фактического проигрывания, не при загрузке.
* Обычный `POST /chat` принимает `ref_kind=video`, `ref_id=<catalogue id>`.
  Проверка видео и серверный заголовок сохраняют общую идемпотентность чата.

Video: `id,title,description,author,source_url,media_url,thumbnail_url`
(nullable), `license_name,license_url,topics:[id],language,duration_seconds,
aspect_ratio,liked:bool,saved:bool,hidden:bool,plan_card_id` (nullable).
Последнее поле — только существующий доступный взаимный план при актуальном
особом согласии; иначе null. Видео само не даёт согласие и не запускает план.

## Каталог и хранение

Стартовый JSON `backend/app/content/videos.json` содержит перечисленные
публичные поля (без liked/saved/hidden/plan_card_id), `reviewed_at`, `active`,
необязательные `plan_deck` и `plan_text` для точного сопоставления существующей
карточки в конкретной базе. Только HTTPS, утверждённые конкретные хосты, явные автор,
страница источника и лицензия; никакого HTML из источника и произвольных URL
от пользователя. На сервере нет скачивания медиа по переданному URL.
Тесты используют собственный небольшой каталог, независимо от редакторского.

Новые таблицы только добавляются миграцией `0004_videos`: личные настройки,
явно общие темы, личные состояния роликов. Личные поля зашифрованы существующим
Encrypted. Удаление аккаунта очищает личное; завершение пары — общие темы и
уже существующий чат. Личные отметки не отправляют уведомления партнёру.
Общие темы обновляют scope `us`, отправка ролика — обычный scope `chat`.

## Flutter

Новый маршрут `/videos` (mode через query) и `/videos/:id`, полноэкранная
вертикальная листалка; entry во «Вместе», компактный preview на «Сегодня»,
личные сохранения и явно отправленные ролики в «Пара». Interests sheet
показывает разницу между личными и общими темами. Никакой новой шестой вкладки.

Один активный плеер, остальные не загружают видео. Пауза при уходе с маршрута,
фоне, блокировке, смене аккаунта и звонке. Сессия не должна показывать данные
предыдущего пользователя. Управление воспроизведением, звуком, повтором,
источник/автор/лицензия, ошибка с повтором и открытием источника. Нормальное
соотношение сторон; горизонтальные ролики не выдаются за вертикальные.
Встроенный Android-плеер через официальный video_player, pin после проверки
совместимости, тестируемая граница плеера. Экран API9 без новых маршрутов
объясняет, что нужно обновление сервера, без необработанной ошибки.

«Отправить партнёру» открывает существующий чат с вложением для явной отправки.
Подпись «В Пара» означает общий список явно отправленного. Кнопки лайка и
сохранения относятся к «Вечеру», не меняют аккаунты внешних сервисов.

Вместе получает кнопку повтора ошибки и AlwaysScrollableScrollPhysics.
Обновление необязательное, старые клиенты продолжают работать. Выпуск требует
проверок SQLite/PostgreSQL/Flutter, изолированной репетиции миграции и
совместимого восстановления, новой сборки с прежним Android-ключом.

## Доработка по результатам использования APK 10

22 октября владелец сообщил об установленном обновлении, частичных отказах
воспроизведения и необходимости более точного подбора. Причина конкретных
сетевых отказов пока не установлена. Исправление фильтрации использует текущую
схему `0004_videos`; новые таблицы и сбор времени просмотра для него не нужны.

План собственной медиадоставки, пополнения каталога и проверки четырёх сетевых
режимов: [VIDEO_RELIABILITY_PLAN.md](VIDEO_RELIABILITY_PLAN.md). Подготовленные
изменения исходников не означают обновления установленного APK или сервера.
