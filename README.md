# Вечер

Приватное приложение для совершеннолетних пар — рядом и на расстоянии. Монорепозиторий:

| Папка | Что внутри |
|---|---|
| `app/` | Мобильное приложение (Flutter, iOS + Android) |
| `backend/` | API (FastAPI + PostgreSQL) |
| `infra/` | Docker Compose: PostgreSQL, Redis, Centrifugo, Directus, API |

Сейчас готово: вход по коду на e-mail, приглашение партнёра по коду, экран «Сегодня» — вопрос дня (ответ партнёра открывается после своего), дневной радар и огонёк пары; «Вместе» — свайпер карточек, где партнёр видит только взаимное, и бесплатные планы к совпадениям (выбор варианта вдвоём, список продуктов, «Запланировать»); «Я» — личные письма и сюрпризы; «Пара» — памятка о партнёре, «о себе», личные заметки, важные даты («вместе N дней») и напоминания себе, партнёру или обоим.

## Бесплатный основной продукт

По решению владельца от **22 октября 2026 года** основной «Вечер» полностью
бесплатен. Чат, файлы, звонки, вопросы, желания, планы, письма и функции пары
доступны без подписки «Вечер+». Планы открываются без числовой квоты; правила
взаимности, согласия, приватности и технические ограничения загрузок сохраняются.

Платным планируется только будущий необязательный раздел **«Вечер 18+»** внутри
приложения. По уточнению владельца сначала полностью завершаем и проверяем
бесплатную версию и только затем начинаем разработку платного раздела.
В этой версии раздел и оплата ещё не реализованы. Прежние записи
подписок не дают автоматического доступа к будущему разделу.

API сохраняет совместимость с APK 6 и 7. В новом клиенте убран экран «Вечер+»;
старые клиенты после обновления API смогут бесплатно открывать все доступные
планы, хотя до обновления APK у них останется прежняя статическая подпись.
Контракт, границы изменения и порядок проверки: [PRODUCT_RULES.md](PRODUCT_RULES.md).

Ближайший выпуск бесплатного доступа — отдельный пакет **0.3.1 (8)**, PR #3.
Он прошёл проверки кода, но ещё не установлен на сервер и телефоны.

## Прохождение вечера — подготовка 0.4.0 (9)

После взаимного выбора вариант можно пройти вместе: отмечать выполненные
и пропущенные шаги, поставить паузу, продолжить и завершить. Текущий вечер
доступен с «Сегодня», история — из «Пары». Новое прохождение сохраняет старую
историю; оценка результата необязательна и видна только её автору.
Контекст «Рядом / Отдельно» выбирается для конкретного вечера, без закрепления
пары за одним режимом.

Это следующий подготовленный пакет кода. Он не означает, что APK 9 уже собран
или установлен. Нужна схема `0003_evenings`; старый API 0.3.x ожидает другую
версию схемы и не подходит для простого возврата после этой миграции.
Критерии завершения всего бесплатного этапа: [FREE_CORE_ACCEPTANCE.md](FREE_CORE_ACCEPTANCE.md).

## Чат, файлы и видеозвонки — версия 0.2

- Уведомления внутри приложения показываются сверху. Когда чат виден, уведомление о новом сообщении в нём не появляется; фоновый или закрытый кодом-паролем чат не отмечает сообщения прочитанными.
- Скрепка в чате позволяет выбрать файл до **25 MiB**, добавить подпись, отменить загрузку и повторить её при сбое. Одно и то же отправление не создаёт дубликатов. Партнёр скачивает файл через авторизованный API. Квота по умолчанию — **250 MiB на пару**.
- Кнопка камеры открывает видеозвонок 1:1. Камера и микрофон запрашиваются после принятия звонка. WebRTC нацелен на 720p/30 fps и снижает нагрузку при плохой сети; доступны выключение микрофона/камеры, смена камеры и устройства звука.
- Для мобильных сетей нужен настроенный **собственный TURN**. В staging звонки включаются только после его настройки. Медиа не записывается API. Файлы и временные сигналы шифруются серверными ключами хранения; это не описание сквозного шифрования всего приложения.

Проверенная среда разработки: **Flutter 3.47.7 / Dart 3.13.5**, Python 3.12. Зависимости клиента закреплены в `app/pubspec.lock`; существующий `flutter_secure_storage` сохранён для совместимости установленных приложений.

## Синхронизация и очередь уведомлений — выпущена 0.3.0 (7)

API сохраняет изменение и уведомление в одной транзакции. Фоновый worker
доставляет сохранённые события через FCM или Centrifugo. Открытое приложение
подписывается только на свой канал и получает список областей для обновления;
сами данные по-прежнему читает через авторизованный REST. После сбоя сети
выполняется сверка, при отключённой синхронизации остаётся прежний опрос.

Владелец опубликовал сборку 7, обновил телефоны и подтвердил работу приложения.
Проверенный выпуск принят в `main`; дальнейшие пакеты получают новые номера.

Схема БД управляется Alembic. В staging перед запуском новой версии требуется
явная миграция после бэкапа: `python -m app.migrate upgrade`; проверка —
`python -m app.migrate check`. Рабочая версия 0.2.1 (6) совместима с новым API.

Согласованный порядок развития: [ROADMAP.md](ROADMAP.md).
Установка, возврат и проверка APK 7: [ROLLOUT_REALTIME.md](infra/staging/ROLLOUT_REALTIME.md).

Порядок обновления работающего сервера и телефонов: [infra/staging/ROLLOUT_CHAT_CALLS.md](infra/staging/ROLLOUT_CHAT_CALLS.md). Настройка TURN: [infra/turn/README.md](infra/turn/README.md). Перед выпуском проверяются два телефона, доставка входящего push, Wi-Fi ↔ мобильная сеть и принудительная передача через TURN; локальные тесты не подтверждают качество реальной связи.

## 1. Установить инструменты (Windows, один раз)

1. **Git** — https://git-scm.com/download/win (всё по умолчанию).
2. **Docker Desktop** — https://www.docker.com/products/docker-desktop/ (после установки перезагрузить ПК и запустить Docker Desktop).
3. **Flutter SDK** — https://docs.flutter.dev/get-started/install/windows/mobile
   - распакуйте в `C:\dev\flutter` (не в Program Files);
   - добавьте `C:\dev\flutter\bin` в переменную PATH;
   - откройте новое окно PowerShell и выполните `flutter doctor`.
4. **Android Studio** — https://developer.android.com/studio
   - при первом запуске поставьте Android SDK;
   - More Actions → Virtual Device Manager → создайте эмулятор (например, Pixel 7);
   - выполните `flutter doctor --android-licenses` и согласитесь со всем.
5. **Python 3.12** (для тестов сервера без Docker) — https://www.python.org/downloads/ (галочка «Add to PATH»).

Проверка: `flutter doctor` должен показать зелёные галочки у Flutter, Android toolchain и Android Studio.

## 2. Запустить сервер

### Вариант А — быстро, без Docker (Python + локальная база SQLite)

```powershell
cd C:\dev\vecher\backend
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dev.txt
uvicorn app.main:app --reload --port 8090
```

Окно не закрывайте — сервер работает, пока оно открыто. Проверка: http://localhost:8090/docs

### Вариант Б — локальный набор в Docker (PostgreSQL, Redis, Centrifugo, Directus)

```powershell
cd vecher\infra
copy .env.example .env
notepad .env          # замените все «замените-меня» на случайные строки
docker compose --env-file .env up -d --build
```

Локальная синхронизация включается `VECHER_REALTIME_ENABLED=true` после задания
двух разных случайных секретов Centrifugo. Для браузера используйте порт 5000,
который входит в разрешённые Origin. Рабочий сервер использует отдельный
`infra/staging/docker-compose.yml` и сценарии миграции из документа выпуска.

Проверка в браузере:
- http://localhost:8090/health — `{"ok": true, ...}`
- http://localhost:8090/docs — все методы API, можно пробовать прямо там
- http://localhost:8055 — админка контента Directus (логин и пароль из `.env`)

Остановить: `docker compose down` (данные сохраняются).

## 4. Запустить приложение

Первый раз — сгенерировать папки платформ (android/ios), код в `lib/` не тронется:

```powershell
cd vecher\app
flutter create --org online.vecher --project-name vecher_app --platforms android,ios,web .
flutter pub get
```

Самый быстрый способ посмотреть приложение — в браузере (Android и эмулятор не нужны):

```powershell
flutter run -d chrome --web-port 5000
```

Адрес будет всегда один: http://localhost:5000. Второго партнёра удобно открыть в другом браузере
(Яндекс, Edge) или в окне инкогнито по тому же адресу — у каждого свой вход.

Если экран пустой или белый:
1. В окне `flutter run` нажмите `R` (большая) — полный перезапуск; или F5 в браузере.
2. Посмотрите красные строки в окне `flutter run` (начинаются с `VECHER ERROR` или `EXCEPTION`)
   и в браузере: F12 → Console.

Разрешить HTTP к локальному серверу в отладке: откройте `app\android\app\src\debug\AndroidManifest.xml`
и в тег `<manifest ...>` добавьте внутрь:

```xml
<application android:usesCleartextTraffic="true" />
```

Запуск (эмулятор должен быть открыт):

```powershell
flutter run
```

Вход: в режиме `dev` API возвращает тестовый код в поле `dev_code`; приложение
показывает его в отладочной консоли Flutter. Сервер не записывает коды входа
в журнал. В staging/prod требуется настроенная SMTP-почта.

Чтобы проверить пару, запустите приложение на двух эмуляторах (или эмулятор + телефон) с разными e-mail:
один нажимает «Получить код», второй вводит его в «У меня есть код».

- Секреты только в `.env`, в git не попадают.
