# Публикации и авторы

Модуль `/content` добавляет полезные посты, инструкции и явно выбранные ссылки
на проверенные видео. Тексты, авторы, темы и источники — публичный редакционный
снимок. Личные интересы, подписки на авторов, скрытия, отметки «полезно» и
сохранения — отдельные зашифрованные данные пользователя. Модуль не читает чат,
письма, тихие желания, ответы пары, длительность чтения или просмотра.

Существующие `/videos`, идентификаторы роликов, сохранения и отправленные в чат
ссылки на видео продолжают работать. Старые ролики автоматически не попадают
в новую подборку. Публикация `kind=video` должна явно ссылаться на действующий
проверенный `video_id`; её сохранение относится к публикации, прежнее
сохранение самого ролика остаётся в `/videos`.

## Выбор публикаций

Все запросы требуют входа и действующего общего согласия. Личная подборка,
авторы, подписки и сохранённое доступны без пары и без специального согласия.
Общие настройки и общая подборка требуют действующей пары.

| Режим | Отбор |
| --- | --- |
| `personal` | Только выбранные личные темы и язык. Несколько тем образуют объединение. Пустой выбор тем даёт пустую подборку. |
| `following` | Только явно выбранные авторы и личный язык, независимо от личных тем. Без подписок подборка пустая. |
| `shared` | Только отдельно выбранные общие темы и язык. Личные темы партнёров не объединяются и не копируются. Пустой выбор даёт пустую подборку. |
| `saved` | Собственные сохранения независимо от тем, языка и скрытий. Отозванные редакцией публикации недоступны. |

Обычная личная подборка, подписки и общая подборка учитывают собственные
скрытия читателя. Эти скрытия не меняют выбор партнёра. Прямое открытие автора
или серии в `personal` — отдельное намеренное действие: оно не ограничивается
личными темами, языком или скрытием автора. При этом скрытые отдельные
публикации остаются скрытыми в списке; прямой экран публикации и сохранённое
позволяют отменить скрытие. В общем режиме фильтр автора/серии не отменяет
общие темы и язык.

Язык `ru` или `en` также допускает материалы `none` без слов. `all` допускает
любой поддерживаемый язык. Порядок обычной подборки — дата публикации и
стабильный ID; серии — `series_order`; сохранённого — последнее явное
изменение собственной отметки. Неявного профиля по времени чтения нет.
«Полезно» хранится как собственная явная отметка; скрытого обучения по ней
или глобального счётчика популярности в этом выпуске нет.

## API

`GET /content/settings`:

```json
{
  "topics": [{"id": "digital", "title": "Цифровые навыки", "available": true, "published_count": 3}],
  "languages": [{"id": "ru", "title": "Русский"}, {"id": "en", "title": "English"}, {"id": "none", "title": "Без слов"}, {"id": "all", "title": "Все языки"}],
  "personal_topics": [],
  "personal_language": "ru",
  "personal_revision": 0,
  "shared_topics": [],
  "shared_language": "ru",
  "shared_revision": 0,
  "followed_author_ids": [],
  "hidden_author_ids": [],
  "has_pair": false,
  "catalogue_revision": "sha256"
}
```

Список тем содержит все объявленные редакцией темы, `available` и количество
активных публикаций. Тема без материалов остаётся видимой для отмены выбора.
Ранее выбранные ID сохраняются, даже если редакция отозвала последний
материал такой темы: это не должно включать произвольные другие темы.

`PUT /content/settings/personal` и `PUT /content/settings/shared` принимают
`{"topics":["digital"],"language":"ru","revision":0}`. Ответ — актуальные
настройки. Устаревшая ревизия возвращает `409`, повторная запись тех же
настроек с текущей ревизией не создаёт изменения. Подписки и скрытия автора
также меняют личную ревизию, чтобы второй экран не затёр новые настройки.
Клиент при `409` перечитывает настройки и предлагает повторить выбор.

`GET /content/feed?mode=personal&limit=20&cursor=...&q=...&author_id=...&series_id=...`
принимает лимит 1–50, поиск до 120 символов и необязательные публичные ID.
Поиск ищет все слова запроса в заголовке, аннотации, тексте и имени автора
внутри выбранного набора. Ответ:

```json
{
  "items": [],
  "next_cursor": null,
  "total": 0,
  "mode": "personal",
  "catalogue_revision": "sha256"
}
```

Курсор подписан HMAC, содержит только непрозрачный отпечаток и смещение.
Он привязан к пользователю, паре для общего режима, режиму, поиску, автору,
серии, лимиту, редакционному снимку, доступности видео и ревизиям собственных
состояний/настроек. Изменение или отмена отметки между страницами приводит
к `409`, даже если её итоговое значение вернулось к прежнему. Клиент начинает
подборку заново; он не склеивает страницы разных версий. Личные изменения
партнёра не меняют курсор. Повреждённый курсор возвращает `422`.

`GET /content/{id}` возвращает опубликованный материал с полным текстом:

```json
{
  "id": "stable-id",
  "kind": "guide",
  "title": "Название",
  "summary": "Краткое содержание",
  "author": {"id": "author-id", "name": "Автор", "bio": "Описание", "url": null},
  "topics": ["digital"],
  "language": "ru",
  "blocks": [{"type": "heading", "text": "Раздел"}, {"type": "paragraph", "text": "Текст"}, {"type": "list", "items": ["Первый шаг"]}],
  "sources": [{"title": "Источник", "url": "https://example.org/source"}],
  "published_at": "2026-10-23T00:00:00Z",
  "updated_at": "2026-10-23T00:00:00Z",
  "reading_minutes": 3,
  "series_id": null,
  "series_title": null,
  "series_order": null,
  "video_id": null,
  "useful": false,
  "saved": false,
  "hidden": false,
  "author_followed": false,
  "author_hidden": false
}
```

`PATCH /content/{id}/state` принимает хотя бы одно явное булево поле
`useful`, `saved`, `hidden`, возвращает публикацию. Значения `null`, числа,
строки и неизвестные поля отклоняются. Запись задаёт значение, а не
переключает его: безопасный повтор не меняет ревизию, дату и уведомления.
Конкурирующие изменения разных полей одного пользователя объединяются
под блокировкой пользователя.

`GET /content/authors` возвращает `{"items":[...]}`. В том числе показываются
скрытые авторы, чтобы скрытие можно было отменить. `GET /content/authors/{id}`
возвращает автора с `published_count`, `followed`, `hidden`.
`PATCH /content/authors/{id}/state` принимает явные `followed` и/или `hidden`,
возвращает автора. Подписка и скрытие независимы: снятие скрытия не требует
повторной подписки.

Успешные ответы имеют `Cache-Control: private, no-store` и
`Vary: Authorization`. Приватное действие создаёт invalidation только для
самого читателя (`solo`), изменение общих настроек — для участников пары
(`us`). В событии нет тем, автора, ID материала или текста. Отправка
партнёру выполняется обычным редактируемым черновиком сообщения с названием
и аннотацией; API чтения ничего не отправляет.

## Редакционный снимок

По умолчанию используется `app/content/publications.json`. Для обновления
публикаций без сборки APK и перезапуска API администратор задаёт
`VECHER_CONTENT_CATALOGUE=/managed-editorial/publications.json` и монтирует
**каталог целиком** в API только для чтения. Отдельный bind mount одного файла
может продолжить видеть старый inode после атомарной замены. Переменная
читается модулем каталога независимо от настроек БД.

Верхний объект содержит `version:1`, `topics`, `authors`, `items`.
Публикация дополнительно к публичным полям содержит `author_id`,
`reviewed_at` (дату редакционной проверки) и явный `active`.
Текстовые блоки ограничены `heading`, `paragraph`, `list`; HTML, iframe,
неизвестные поля и невалидные ссылки отклоняются. URL источника или автора
должен быть HTTPS, без учётных данных, IP-адреса, локального имени или
нестандартного порта. API эти URL не запрашивает и не пересылает им токен.

Снимок ограничен 8 МиБ, 5 000 публикациями, 500 авторами и 80 темами.
ID уникальны, ссылки на авторов/темы проверяются, у серии единые автор и
название, номера внутри неё уникальны. Даты имеют часовой пояс.
`active` является явным разрешением публикации; одна только будущая дата
не включает отложенную публикацию. ID сохраняется при исправлении текста;
при отзыве материала редакция ставит `active:false`.

На Linux в окружении backend:

```sh
python -m app.publish_content --source candidate.json --check-only
python -m app.publish_content --source candidate.json --destination /managed-editorial/publications.json --create
python -m app.publish_content --source candidate.json --destination /managed-editorial/publications.json --expected-revision CURRENT_SHA256
```

Первая команда только проверяет кандидат. `--create` допускает только
отсутствующий итоговый файл. Последующие публикации требуют ревизию именно
того снимка, который редактор проверил. CLI валидирует весь кандидат,
проверяет ссылки на видео, берёт межпроцессную блокировку, сравнивает текущую
ревизию, записывает и синхронизирует временный файл в том же каталоге,
атомарно заменяет снимок и синхронизирует каталог. До замены ошибка оставляет
предыдущую версию. После замены API замечает новый снимок при следующем
запросе. CLI публикует только публичные данные с режимом `0644`.

Каталог должен принадлежать доверенному процессу публикации; API не получает
право записи. CMS может готовить кандидат, но не получает доступ к приватной
БД приложения. Сам интегратор CMS не является частью этого модуля. Если
выбранный снимок повреждён, API возвращает `503` для публикаций без утечки
пути или содержимого черновика; остальные разделы продолжают работать.

## Данные и миграция

Ревизия Alembic `0005_content` следует за `0004_videos`. Она создаёт
`content_preferences`, `shared_content_preferences`, `content_states`.
Настройки и состояния шифруются существующим `Encrypted`/`DATA_KEYS`;
публичные ID публикаций и ревизии позволяют адресовать собственные строки.
История просмотра и время чтения не создаются.

Завершение пары стирает только общие настройки. Удаление аккаунта стирает
его настройки и отметки. `ON DELETE CASCADE` сохраняет это поведение и при
совместимом восстановительном образе, который не знает названий новых
таблиц. Автоматического downgrade с потерей личных данных нет.

Тесты проверяют приватность между участниками, согласие, ограничения тем,
авторов и языка, поиск, страницы без дублей, устаревшие курсоры, повторные
запросы, конкурентные записи, зашифрованное хранение, удаление, сохранность
старых видео, валидацию и атомарную публикацию. Миграционные тесты используют
реальную предыдущую схему, проверяют сохранность строк и откат сбоя DDL.
