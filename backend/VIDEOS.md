# Видео: совместимость и официальные плееры

Раздел остаётся частью существующих личных и общих подборок. Новые обычные
подборки используют проверенные публичные материалы RUTUBE. Ранее сохранённые
и отправленные ролики Wikimedia остаются доступны по прежним идентификаторам.
Изменения схемы базы данных не требуются.

## Два контракта API

Все маршруты `/videos` принимают параметр `playback`:

| Значение | Назначение |
| --- | --- |
| `legacy` (по умолчанию) | Установленные старые APK: только прямые файлы, прежние поля ответа |
| `platform-v1` | APK с поддержкой официального плеера RUTUBE и старых прямых файлов |

Параметр передаётся в GET/PUT настроек, GET подборки/общей коллекции/карточки,
PATCH отметок и POST просмотра. Это явная возможность клиента, а не переключатель
согласий или доступа к чужим данным. Авторизация, согласия, границы пары и
проверка ревизий настроек остаются обязательными.

Клиент `platform-v1` получает дополнительные поля:

```json
{
  "id": "rutube-<32 lowercase hexadecimal characters>",
  "playback_kind": "rutube_embed",
  "provider_video_id": "<32 lowercase hexadecimal characters>",
  "source_url": "https://rutube.ru/video/<provider_video_id>/",
  "embed_url": "https://rutube.ru/play/embed/<provider_video_id>",
  "media_url": null,
  "license_name": null,
  "license_url": null
}
```

Для прежних роликов `playback_kind` равен `direct`, `provider_video_id` и
`embed_url` равны `null`, остальные сведения о файле и лицензии сохраняются.
Для `legacy` три дополнительных поля вообще не отправляются. Запрос старого
клиента к карточке, отметкам или просмотру RUTUBE возвращает HTTP 409 с просьбой
обновить приложение до любых изменений в базе. Неизвестное значение `playback`
возвращает HTTP 422.

В `platform-v1` обычные режимы `personal` и `shared` содержат только RUTUBE.
`saved` и `/videos/shared` могут содержать оба вида. Старый клиент во всех
списках видит только поддерживаемые им прямые файлы. Ссылка на новый материал
может быть отправлена в существующий чат: идентификатор и заголовок проверяет
сервер, а старому APK при открытии предлагается обновление.

## Интересы и приватность

Выбранные темы работают как строгий фильтр по объединению выбранных интересов.
Если подходящих материалов нет или пользователь скрыл все подходящие ролики,
подборка остаётся пустой. Несвязанные материалы не подставляются. Пустой список
интересов означает начальную подборку всех доступных материалов этого плеера.

Настройки `platform-v1` возвращают все известные темы с полем `available`.
Оно показывает наличие активного материала RUTUBE по теме. Ранее выбранная тема
сохраняется, даже когда последний подходящий материал отключён; её можно снять
или оставить выбранной. Личные и общие интересы используют прежние стабильные
идентификаторы и отдельные ревизии. Личные сохранения, реакции, скрытия и история
просмотров не раскрываются партнёру. В общей коллекции появляются только
материалы, явно отправленные в чат этой пары.

## Каталоги и проверка источника

* `app/content/videos.json` — прежние прямые файлы Wikimedia, прежние ID,
  продолжительность до 180 секунд и обязательные сведения о лицензии.
* `app/content/rutube_videos.json` — встроенный в образ список RUTUBE,
  продолжительность до 7200 секунд. `media_url`, `license_name` и `license_url`
  отсутствуют либо равны `null`.

Список RUTUBE содержит метаданные публичных страниц, а не скопированные файлы
или извлечённые адреса потоков. Официальный плеер сам запрашивает медиаданные у
платформы. Публичная доступность страницы не объявляется лицензией на повторное
распространение. Проверенные страницы, авторы и ограничения проверки описаны
в `../RUSSIAN_VIDEO_SOURCES.md`.

URL плеера генерируется сервером из 32-символьного ID. Произвольный `embed_url`,
подмена домена, идентификатор с параметрами URL, прямой поток и заявленная
лицензия для платформенного материала не принимаются. Превью RUTUBE разрешено
только с `https://pic.rutube.ru`. Добавление новой платформы требует изменения
и проверки кода. В этой версии каталоги входят в серверный образ; внешний
редактируемый каталог и публикации контента с новыми ID не включены.

Офлайн-проверка обоих каталогов из каталога `backend`:

```sh
python -m app.video_catalogue
python -m app.video_catalogue --platform
```

Первый маркер и хеш совместимы с прежней проверкой публикации APK:
`VIDEO_CATALOGUE_OK=24;REVISION=18513eb1e9ccb698`. Второй маркер имеет вид
`PLATFORM_VIDEO_CATALOGUE_OK=<count>;REVISION=<revision>`; ревизия новой
возможности включает оба вида, поскольку старые сохранения остаются доступны.
Эти команды проверяют структуру, соответствие ID и допустимость URL. Они не
проверяют воспроизведение, доступность через конкретного оператора/VPN,
возрастные ограничения или поведение платформы на телефоне.

## Проверка изменений

`tests/test_videos.py` проверяет прежний формат ответов, разделение возможностей,
строгие интересы, пустые темы, ревизии, старые сохранения/отправки, личные отметки,
доступ партнёров, запрет неподдерживаемых изменений и правила источников.
Тесты API используют временную локальную базу. Проверка плеера на устройстве
остаётся отдельным шагом: воспроизведение, повтор после ошибки, возврат из
фона, переход по официальной ссылке и работа с VPN/без VPN в сетях тестеров.
