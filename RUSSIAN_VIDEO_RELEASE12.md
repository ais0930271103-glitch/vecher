# Вечер 0.7.0 (12): российский видеоплеер и проверка соединения

Кандидат от 23 октября 2026 года. Основа: опубликованная 0.6.0 (11),
commit `466269852cde36470b331e7bc288a92fc4520d43`.
Публикация APK 12 и проверка на телефонах — отдельные последующие действия.

## Почему требуется обновление

После публикации APK 11 владелец сообщил, что часть роликов не открывается,
а при включённом VPN недоступно всё приложение. На предоставленных скриншотах
остался источник Wikimedia Commons. Эти сообщения не устанавливают, вызван ли
каждый отказ сетью, декодером, выбранным VPN или маршрутом к API.

Смена видеоплощадки решает источник новых роликов. Для диагностики API требуется
сравнение результатов на одном телефоне с VPN и без него. Новый релиз не
объявляет эти две причины одной проблемой и не обещает доступ через любой VPN.

## Что изменено

- В обычной личной и общей подборке нового клиента — официальный плеер RUTUBE.
  Прямые потоки не извлекаются, видео не скачиваются на сервер Вечера.
- Начальные семь карточек: два рецепта, два научных опыта, садоводство,
  столярные приёмы и авторский походный фильм. Длительности от 35 секунд до
  32 минут 10 секунд указаны по публичным страницам. Это небольшой каталог;
  полноценное регулярное редакционное пополнение ещё требуется.
- Отбор строго по выбранным темам. Пустые темы помечены, ранее выбранные
  интересы сохранены. Другие ролики вместо отсутствующей темы не подставляются.
- Сохранённые и отправленные друг другу старые материалы сохраняют ID,
  источник, лицензии и отметки. Каталог Wikimedia не переписан.
- Плеер запускается нажатием пользователя, использует качество `auto` и
  официальные элементы управления. При закрытии, PIN, фоне или смене сессии
  удаляется iframe; новый плеер ждёт закрытия предыдущего. Полный экран
  учитывает те же ограничения. При области меньше 320×180 предлагается
  открыть источник отдельно.
- После ошибки есть явный повтор и открытие страницы RUTUBE. Площадка может
  показывать рекламу и получать обычные данные просмотра. Токены Вечера,
  содержимое чатов и выбранные интересы в плеер не передаются.
- В настройках и на экране входа появилась ручная проверка подключения:
  анонимный `GET /health`, ограничение 20 секунд, категория ошибки, браузерная
  проверка и копирование отчёта только по нажатию. VPN обозначает сам человек.
- Исправлены два воспроизведённых дефекта клиента: поздний успех старого адреса
  больше не перезаписывает текущий статус; отменённый запрос удаляет таймер,
  который прежде мог позднее ошибочно показать отсутствие связи.

Архитектура, пять основных разделов, личные/общие интересы, чат, звонки и
бесплатность основного приложения сохраняются. Таблицы и схема базы не меняются:
`0005_content`. Настройки coturn, Caddy и проекта KRUG не затронуты.

## Контракт и зависимости

Новый клиент явно передаёт `playback=platform-v1` во всех запросах `/videos`.
Старый APK продолжает получать прежний DTO, а для нового платформенного ID —
управляемый ответ о необходимости обновления до записи отметок. Подробности:
[backend/VIDEOS.md](backend/VIDEOS.md).

Flutter 3.47.7 / Dart 3.13.5, `webview_flutter 4.14.1`,
`webview_flutter_android 4.14.1`; lockfile закреплён. Flutter уже устанавливает
Android minSdk 24. API 0.7.0 использует прежние зависимости backend.

Источники и границы проверки каталога:
[RUSSIAN_VIDEO_SOURCES.md](RUSSIAN_VIDEO_SOURCES.md).

## Что подтверждают проверки

Автоматические сценарии проверяют DTO и совместимость старого клиента,
границы личных/общих данных, фильтрацию, отметки, навигацию, жизненный цикл
плеера, порядок освобождения ресурсов, анонимность и отмену диагностики.
Поддельный native player в тестах не подтверждает работу RUTUBE CDN,
рекламы, кодеков или конкретного Android WebView. Нативная компиляция также
не заменяет просмотр на устройстве.

Офлайн-маркеры каталога:

```text
VIDEO_CATALOGUE_OK=24;REVISION=18513eb1e9ccb698
PLATFORM_VIDEO_CATALOGUE_OK=7;REVISION=606eea15797ae24b
```

## Проверка на телефонах после установки

1. На одном телефоне и одной сети выполнить «Проверить соединение» с VPN
   выключенным, затем включённым. Скопировать оба отчёта; отдельно проверить
   ту же кнопку открытия `/health` в браузере. При исключениях VPN браузер
   и Вечер должны использовать сопоставимый маршрут.
2. Проверить холодный запуск с уже включённым VPN и переключение VPN во время
   открытого приложения. Указать название VPN, наличие исключений и тип сети;
   конфиги, пароли и токены для этой проверки не нужны.
3. Открыть несколько RUTUBE-материалов выбранных тем, звук, полный экран,
   паузу и возврат, сохранение и отправку партнёру. Сравнить Wi-Fi и мобильную
   сеть с VPN и без него. Проверить открытие источника при отказе embed.
4. Во время просмотра свернуть приложение, включить PIN и принять звонок:
   видео не должно продолжать звучать. После возвращения запуск — вручную.
5. Проверить обычный чат, вложение, звонок и обновления в обоих сетевых режимах.

У приложения пока один фактически настроенный API origin. Резервный узел,
DNS или транспорт меняются по результату этих измерений; данный кандидат
не создаёт новый сервер и не обходит системный VPN.
