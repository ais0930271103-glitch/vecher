ВЕЧЕР — ДИАГНОСТИКА ORIGIN И HTTPS

Назначение: разобрать результат R2, в котором путь репозитория совпал,
SSH-хост отличается от github.com, а HTTPS-запрос с Windows не прошёл.
Это отдельная диагностика, не новый пакет развёртывания.

Собрать один переносимый файл:
  python3 infra/staging/release14/build_access_check.py /path/to/vecher-check-origin-https.ps1

На исходном Windows-компьютере:
  powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:USERPROFILE\Downloads\vecher-check-origin-https.ps1"

Сценарий использует существующий alias vecher и прежний jump-host.
Он проверяет назначение alias root@94.228.166.214:22 и передаёт Python-код
через stdin одного SSH-сеанса. Установка файлов на сервер не требуется.

ВЫВОД

WINDOWS_POWERSHELL_HTTPS — результат Invoke-RestMethod с Windows.
WINDOWS_CURL_HTTPS — независимая проверка curl.exe: HTTP-код, exit code,
время DNS/TCP/TLS и категория ошибки. HTTP000 означает отсутствие ответа.

Серверный JSON содержит:
- git: количество исходных и фактически используемых URL, тип транспорта,
  совпадение пути проекта, наличие переопределений без их значений;
- ssh: конечный SSH-хост как безопасная категория, соответствие пользователя
  git, категория порта, признаки proxy и проверки host key. Если конфигурацию
  нельзя безопасно проверить, resolution_performed=false и указана причина;
- server_api_local, server_apk_local: действующие ответы локального API;
- server_public_https: HTTPS-проверка с самого сервера, с обычной проверкой TLS.

ssh -G выполняется только после проверки допустимых аргументов и ограниченного
чтения SSH-конфигурации. Match exec и неподдерживаемые Include не исполняются.
До реальной аутентификации GitHub эта диагностика не доходит.

Маркер VECHER_ACCESS_CHECK_FINISHED означает завершение сбора результатов.
Он не означает успешность всех сетевых проверок или разрешение развёртывания.
Windows, localhost и публичный HTTPS с сервера — разные точки проверки;
успех одной не подменяет результат другой.

Origin, SSH/VPN-настройки, ключи, checkout, контейнеры, БД и APK сценарий
не изменяет. Raw URL, имена ключей, ProxyCommand и полные исключения не выводятся.
Результат используется для точного исправления release runner после проверки
фактического SSH-псевдонима и причины клиентского HTTPS-сбоя.
