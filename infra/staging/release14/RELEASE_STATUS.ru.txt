ВЕЧЕР 0.9.0 (14) — ПАКЕТ ПОДГОТОВКИ R2

R2 исправляет два выявленных ограничения инструментов выпуска:
- Проверка server origin принимала только HTTPS. Теперь точный список
  разрешает также git@github.com:ais0930271103-glitch/vecher и
  ssh://git@github.com/ais0930271103-glitch/vecher с необязательным .git.
  Чужой owner/repo/host, SSH aliases, лишние части URL и несколько origin URL
  не принимаются. Настройка origin не переписывается.
- После раннего отказа до checkpoint команда Status не могла показать
  состояние. Теперь она возвращает phase=no_checkpoint, false для readiness
  и безопасную классификацию Git-настройки; действующий API не изменяется.

ФАКТЫ О ПОКАЗАННОЙ ОШИБКЕ

В пользовательском выводе подтверждены проверка пакета, SSH-подключение,
загрузка helper-файлов и их хеши. WRONG_ORIGIN возник после проверки исходного
HEAD13 и чистоты checkout, до первого обращения preflight к Docker.
Checkpoint, остановка API, резервная копия, миграция и сборка APK этим запуском
не выполнялись. Могли быть созданы служебные каталог инструментов и lock-файлы.

Фактический origin в исходном журнале отсутствует. Нельзя считать SSH доказанной
причиной. R2 поддерживает штатные формы; Status позволяет понять оставшееся
несовпадение без вывода URL или credentials. Не подменяйте origin и не снимайте
проверку вручную. При неподдерживаемом формате сначала нужен разбор настройки.

ПОРЯДОК ПРОДОЛЖЕНИЯ

1. Используйте vecher-release-0.9.0-14-r2.zip в новой отдельной папке.
   Выполните Status и проверьте показанные сведения. При штатном origin
   и прежнем чистом checkout можно повторить Prepare по README.ru.txt.
2. Prepare проверит сервер, создаст согласованную резервную копию и повторит
   её восстановление в изоляции до миграции. Затем подготовит API 0.9.0,
   включит блоги и соберёт APK14 существующей подписью на прежнем Windows-PC.
3. Выполните DEVICE_CHECKS.ru.txt на физических Android-устройствах.
   Accept записывает фактическую приёмку конкретного APK и связанных файлов.
4. Отдельный Publish публикует принятые байты без пересборки и проверяет
   полный публичный APK по HTTPS: размер и SHA256.

ГРАНИЦЫ ГОТОВНОСТИ

ready_for_prepare=true в готовом пакете разрешает подготовку, а не означает,
что сервер обновлён или APK14 выпущен. На момент упаковки R2 signed Windows
build, физическая Android-приёмка и публикация ещё не подтверждены.
Размер и SHA256 APK14 остаются неизвестными до настоящей сборки.

Сохраните checkpoint после обновления: в нём находится действующий
runtime-compose.json. После открытия нового API старую БД автоматически
не восстанавливают; порядок отключения блогов приведён в SERVER_RELEASE.md.
