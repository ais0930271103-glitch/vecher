ВЕЧЕР 0.9.0 (14) — ПРИЁМКА КОНКРЕТНОГО APK НА ANDROID

Перед началом сохраните APK, version.json и source.json, полученные Build.
Проверяются эти байты; после изменения APK приёмка недействительна.
Используйте отдельные тестовые аккаунты двух участников пары и читателя.
Снимите небольшой собственный ролик со звуком. Действия выполняются на тестовом
сервере; публикация читателям требует проверки оператором точной версии поста.

1. ОБНОВЛЕНИЕ И ОСНОВНЫЕ ФУНКЦИИ
Установите APK14 поверх существующего приложения. Вход, пара, сообщения и звонок
работают. Прежнее «Интересное», сохранения и подборки открываются.
На устройстве, где ещё установлен APK13, прежняя лента и старые видео работают;
новый неподдерживаемый формат туда не приходит. Не понижайте версию с удалением
данных ради этого теста.

2. ЛИЧНЫЙ БЛОГ И НАСТОЯЩЕЕ ВИДЕО
«Интересное» -> «Мои блоги» -> личный блог. Укажите публичное имя/описание.
Загрузите снятый телефоном MP4/MOV до 100 МиБ и трёх минут. Добавьте заголовок,
описание, темы. Видны загрузка, обработка, предпросмотр и сохранённый черновик.
Предпросмотр действительно воспроизводит изображение и звук.

3. ОБЩИЙ БЛОГ И СОГЛАСИЯ
Первый участник создаёт общий блог. Второй подтверждает публичный профиль
на своём устройстве. После согласия обоих появляется «Добавить видео».
Теперь создайте пост и проверьте подтверждения его конкретной версии обоими
участниками. Читатель черновика не видит. До второго подтверждения поста
измените его описание: старая версия согласия должна быть отклонена,
принимается только актуальная версия.
Одно подтверждение не должно автоматически заменять согласие партнёра.

4. ПРОВЕРКА ОПЕРАТОРОМ
Просмотрите очередь на сервере, используя существующий SSH alias:

  ssh vecher "cd /opt/vecher-test/repo/infra/staging && docker compose --project-name vecher-test exec -T api python -m app.blog_review list --status pending_review"

Для выбранного тестового поста прочитайте подробности:

  ssh vecher "cd /opt/vecher-test/repo/infra/staging && docker compose --project-name vecher-test exec -T api python -m app.blog_review show POST_ID"

Замените POST_ID, REVISION, BLOG_REVISION и MEDIA_SHA256 данными из show.
Убедившись в содержании тестового ролика, подтвердите именно эту версию:

  ssh vecher "cd /opt/vecher-test/repo/infra/staging && docker compose --project-name vecher-test exec -T api python -m app.blog_review approve POST_ID --revision REVISION --blog-revision BLOG_REVISION --sha256 MEDIA_SHA256"

Не подставляйте произвольные номера/хеши и не подтверждайте чужие материалы
только ради завершения теста. Другой revision требует нового просмотра.

5. ЧИТАТЕЛЬ И ПОДПИСКА
Отдельный читатель на APK14 открывает опубликованный пост, смотрит видео
со звуком, перематывает, подписывается на автора/пару. Автор находится в
подписках. Сохранить/скрыть/пожаловаться работают. Новый материал доступен
в подборке с учётом предпочтений; точная позиция рекомендации не фиксирована.

6. СЕТЬ И ПОВТОР
Прервите сеть при загрузке другого тестового ролика, затем повторите.
Состояние понятно, черновик не превращается в дублирующую публичную публикацию.
Проверьте загрузку через обычную мобильную сеть хотя бы на одном устройстве.

7. ВЫБОР ФАЙЛА, ФОН, PIN И ЗВОНОК
Выйдите в системный выбор файла и вернитесь, сверните приложение, включите PIN,
откройте экран звонка. Текст формы сохраняется в текущем аккаунте/паре.
Видео на закрытом/перекрытом экране не продолжает воспроизводиться.
Смена аккаунта не переносит черновик формы между пользователями.

8. СНЯТИЕ ПУБЛИКАЦИИ И ОТЗЫВ СОГЛАСИЯ
Владелец снимает тестовый пост. У читателя новые запросы к этому ролику
закрываются. Для отдельного тестового поста проверьте отзыв публичного
профиля/согласия. Повторное согласие не публикует старые посты автоматически.
Уже загруженные на устройство байты невозможно отозвать задним числом;
проверяется запрет последующих запросов.

9. ЗАПИСЬ РЕЗУЛЬТАТОВ
Запишите модели устройств, версии Android и обнаруженные проблемы.
Если какой-либо сценарий не прошёл, публикацию не запускайте; сохраните вывод
и конкретные шаги воспроизведения. После успешного выполнения всех сценариев:

  powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\run-release14.ps1 -Mode Accept

Сценарий собирает явные ответы и создаёт .phone.json для этих конкретных файлов.
Далее отдельный -Mode Publish публикует тот же APK, без пересборки.
